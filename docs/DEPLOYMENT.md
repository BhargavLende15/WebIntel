# WebIntel deployment guide (Render)

This project is a **React (Vite) frontend**, **FastAPI backend**, and **PostgreSQL** database. The recommended hosted platform is **[Render](https://render.com)** because it matches that shape with minimal ops:

| Component | Render service |
|-----------|----------------|
| PostgreSQL | Managed database (`webintel-db`) |
| Backend API | Docker Web Service (`webintel-api`) |
| Frontend | Static Site (`webintel`) |

Local development stays on `docker-compose.yml`. Production assets live under `docker/` and `render.yaml` without changing app folder layout.

**Alternative (single VPS):** use `docker-compose.prod.yml` to run nginx + API + Postgres on one machine (DigitalOcean Droplet, Hetzner, etc.).

---

## Why Render (and not only Vercel/Netlify)

- **PostgreSQL** is first-class (required for auth, history, scores).
- **Docker** runs the full Python stack (reportlab, scikit-learn, future Playwright).
- **Static site** hosting for Vite build output with build-time `VITE_API_URL`.
- **Blueprint** (`render.yaml`) reproduces the stack from the repo.

Trade-offs on the free tier: services **sleep after inactivity** (cold starts ~30–60s). Upgrade to a paid plan for always-on production.

---

## Prerequisites

1. [Render](https://render.com) account (GitHub login recommended).
2. Repository pushed to **GitHub** or **GitLab** (Render deploys from git).
3. **Google Gemini API key** ([Google AI Studio](https://aistudio.google.com/apikey)) for AI features.
4. A strong **`SECRET_KEY`** (Render can auto-generate for the API service).

---

## Step 1 — Push code

Ensure these files are in your remote branch:

- `render.yaml`
- `docker/Dockerfile.backend.prod`
- `docker/entrypoint.backend.sh`
- `frontend/` and `backend/` unchanged in structure

---

## Step 2 — Create the stack from Blueprint

1. In Render Dashboard → **Blueprints** → **New Blueprint Instance**.
2. Connect your repository and select the branch to deploy.
3. Render reads `render.yaml` and proposes three resources:
   - Database `webintel-db`
   - Web Service `webintel-api` (Docker)
   - Static Site `webintel`
4. Click **Apply**.

Wait until `webintel-api` shows **Live** (first build installs Python deps and runs Alembic migrations via `entrypoint.backend.sh`).

Note the API URL, e.g. `https://webintel-api.onrender.com`.

---

## Step 3 — Configure environment variables

### Backend (`webintel-api`)

| Variable | Value |
|----------|--------|
| `DATABASE_URL` | Set automatically from `webintel-db` |
| `SECRET_KEY` | Auto-generated by Blueprint (or set a long random string) |
| `DEBUG` | `false` |
| `GEMINI_API_KEY` | Your Gemini key |
| `CORS_ORIGINS` | JSON array with your **frontend** origin, e.g. `["https://webintel.onrender.com"]` |

`CORS_ORIGINS` must match the static site URL **exactly** (scheme + host, no trailing slash).

### Frontend static site (`webintel`)

| Variable | Value |
|----------|--------|
| `VITE_API_URL` | `https://webintel-api.onrender.com/api/v1` (use your real API hostname) |

After changing `VITE_API_URL`, trigger **Manual Deploy → Clear build cache & deploy** so Vite embeds the new URL.

---

## Step 4 — Verify deployment

1. **API health:** open `https://<your-api-host>/health` → `{"status":"ok",...}`.
2. **API docs:** `https://<your-api-host>/docs`.
3. **Frontend:** open the static site URL, register/login, run an analysis.
4. If the browser shows CORS errors, fix `CORS_ORIGINS` on the API and redeploy the API.

---

## Step 5 — Custom domain (optional)

1. Render → each service → **Settings → Custom Domains**.
2. Add e.g. `app.yourdomain.com` (static) and `api.yourdomain.com` (API).
3. Update DNS per Render instructions.
4. Update `VITE_API_URL` to `https://api.yourdomain.com/api/v1`.
5. Update `CORS_ORIGINS` to `["https://app.yourdomain.com"]`.
6. Redeploy frontend (clear cache) and restart API.

---

## Deploy on a VPS with Docker Compose (optional)

For one server with a single public URL (nginx proxies `/api` to the backend):

1. Copy env file:

   ```bash
   cp .env.example .env
   ```

2. Set in `.env`:

   - `POSTGRES_PASSWORD` — strong password
   - `SECRET_KEY` — long random string
   - `GEMINI_API_KEY`
   - `CORS_ORIGINS=["http://YOUR_SERVER_IP"]` or your domain
   - `DEBUG=false`

3. Build and run:

   ```bash
   docker compose -f docker-compose.prod.yml up --build -d
   ```

4. Open `http://YOUR_SERVER_IP` (port 80). The frontend uses `VITE_API_URL=/api/v1`; nginx forwards `/api/` to the backend.

5. Put TLS in front (Caddy, nginx + Certbot, or Cloudflare) before production traffic.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| API build fails on migrations | Check `DATABASE_URL` and DB status; logs in Render → `webintel-api` → Logs |
| Frontend calls `localhost` | Rebuild static site with correct `VITE_API_URL` |
| CORS blocked | Add frontend URL to `CORS_ORIGINS` on API |
| `postgres://` connection errors | Fixed in app via URL normalization in `config.py`; redeploy API if on old image |
| Cold start timeout | Free tier spin-down; retry or upgrade plan |
